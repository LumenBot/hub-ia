🤖 Multi-agents par fonction métier

Pattern « un agent par fonction » avec orchestrateur central. Architecture qui simule une équipe étendue sous direction technique automatisée. Vision systémique de la transformation IA.

Le cas

Un membre du ZHC Institute a déployé un système de quatre agents IA spécialisés (Sales, Marketing, Writer, Developer), chacun installé dans son propre canal Discord et alimentant un dashboard unifié. Un agent orchestrateur gère le routage des demandes et les tâches récurrentes (cron jobs).

Le système simule la structuration d'une équipe métier sous une direction technique automatisée. C'est l'illustration aboutie d'un pattern de structuration d'organisation par agents par fonction, transposable aux startups en montée en charge et aux PME/ETI cherchant à augmenter leurs équipes existantes.

L'architecture

  1. 4 agents spécialisés : Sales (qualification, prospection, suivi pipeline), Marketing (production de contenus, analyse), Writer (rédaction longue, ton), Developer (code, automatisation, intégrations)
  2. 1 canal Discord par agent — l'humain communique avec l'agent dédié sur son canal, traçabilité maintenue
  3. Dashboard unifié — agrège les tâches de tous les agents, donne la vision d'ensemble, permet pilotage humain
  4. Agent orchestrateur — route les demandes vers l'agent compétent et déclenche les tâches récurrentes
  5. Pattern « hardening » — un agent à qui on confie une tâche plusieurs fois la transforme en workflow réutilisable

Stack technique

  • Framework agent : OpenClaw (cité massivement par ZHC), LangGraph, Dify, Flowise
  • Modèles : Claude, GPT, Mistral, Kimi K2 selon la tâche
  • Canal d'interaction : Discord (préféré pour multi-agents), Slack, Telegram
  • Dashboard : custom ou Notion / Linear / ClickUp
  • Orchestration transverse : n8n, Make, Zapier
  • Mémoire partagée : vector store (RAG), base SQL

Indicateurs documentés

Non chiffré formellement dans les sources publiques. Témoignages communauté ZHC : plusieurs heures de débogage initial pour stabiliser 5 agents, recommandation forte de commencer par un seul agent supplémentaire avant de multiplier.

Limites et points de vigilance

  • Complexité de déploiement : 1→5 agents multiplie les bugs (mémoire, conflits, perte de contexte)
  • Périmètres flous : duplications ou oublis si responsabilités non délimitées strictement
  • Coût d'inférence : multiplier agents = multiplier appels modèles
  • Gouvernance et responsabilité : sujet AI Act et responsabilité contractuelle
  • Humain dans la boucle obligatoire pour toute action engageante
